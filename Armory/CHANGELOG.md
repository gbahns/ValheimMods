# Changelog

## 1.1.0 — unreleased

- **The rack now works properly for more than one player.** It is a container as well as a loadout station, and it was opening its storage the one way vanilla never does — calling `InventoryGui.Show` straight out of `Interact`. Vanilla asks the ZDO's owner first, and the owner hands the ZDO over before answering; that is not ceremony. `InventoryGui` draws the container panel only while the viewer owns the ZDO, and `Container` saves its inventory only if the viewer owns the ZDO. So a player who did not happen to own it got the loadout panel with no storage grid beside it, and anything moved into the rack — including the gear Load swaps back in — was quietly dropped. The rack now performs the same exchange vanilla does, with its own pair of RPCs.
- The rack opens even though the mod cannot be installed on a dedicated server. Armory is `[BepInProcess("valheim.exe")]`, so BepInEx never loads it under `valheim_server.exe` — and a server owns every persisted ZDO after a restart. A request sent to it would reach a machine with no rack prefab and no handler and be dropped without a word, which would have left the rack simply not opening. The request now carries a deadline, and when it passes the client claims the ZDO itself and opens. A rack you already own skips the exchange entirely, so the usual case costs nothing.
- **A ward protects the rack, and a private rack is private.** The storage was built by hand and kept the bare field defaults rather than the chest's own settings, which made it the one container on the map that ignored guard stones and privacy. It now takes both from the chest it is cloned from, and refuses with the same messages vanilla uses — `$msg_cantopen` when it is not yours, `$msg_inuse` when someone else is already in it.
- **The inventory opens where it belongs when "Pause Game While Armory Open" is on.** The game slides its inventory and container panels into place with an animation, and an animation advances on game time, so holding the clock at zero froze that slide on its first frame: the player's grid sat off the top of the screen and the rack's grid landed on top of what was left of it. The one animation the inventory screen uses now runs on real time for as long as the rack holds the pause, and goes back to game time when the rack closes. The setting has behaved this way since it was added in May, but it defaults to off, so most people will never have seen it.
- **That pause now asks the game for the pause instead of taking it.** It calls vanilla's own `Game.Pause` / `Game.Unpause` — the two calls the ESC menu makes — the way the map and inventory-panel pauses in The Greatest Map and Grab Materials already did. Two things follow. Solo or hosting alone is unchanged. On a dedicated server the request is now refused unless [Pause My Server](https://valheim.thunderstore.io/package/DeathMonger/PauseMyServer/) grants it, where before the rack stopped your clock alone while the server ran on, which is a good way to desync yourself. It also ends a per-frame tug of war: the game assigns the time scale every frame from its own update, so writing it directly only won on script execution order.
- The pause is re-asserted rather than assumed, so anything else letting go of it — the ESC menu closing over the panel, a cinematic ending — no longer silently drops the rack's request.
- Known limitation of the same setting: a craft started from the inventory screen while the rack is open cannot finish, because the craft timer counts game time too. Close the rack before crafting, or leave the pause off.

## 1.0.0 — 2026-09-09

First public release, built for Valheim 1.0.7.

- Armory Rack build piece (Hammer > Furniture; needs a Workbench in range) that is both a storage container and a loadout station.
- Up to 10 named loadouts per rack, each capturing helm, chest, legs, cape, utility, right hand, left hand and hotbar slots 1-8.
- Load pulls gear from the rack first, then your inventory, and stores what you were wearing back into the exact slot the new item came from.
- Live status on each slot, a compare window for current gear versus the saved set, and an optional pause while the panel is open.
- Loadouts are stored in the rack's ZDO, so they survive saves and work in multiplayer.
